# MOVRIT 시연 시나리오 (약 10분)

브랜드가 캠페인을 열고, 새 사용자가 가입해 신청하고, 콘텐츠 제출 후 최종 승인까지 이어지는 흐름을 보여줍니다.
모든 단계는 2026-10-31에 자동 점검 스크립트(Playwright)로 화면에서 끝까지 통과했습니다.

## 준비 (1분)

1. 백엔드: `movrit` 폴더에서 `scripts/integration.sh start` → http://localhost:18080
2. 프론트: `movrit-frontend` 폴더에서 `nvm use && npm run dev:integration` → http://localhost:5174
3. 브라우저 창 3개(일반 창·시크릿 창 등)를 열어 업체·사용자·운영자 계정을 각각 로그인합니다.

| 역할 | 계정(통합 DB 전용 점검 계정) |
|---|---|
| 업체 | `claude-design-brand@movrit.local` (브랜드 'QA DESIGN') |
| 사용자 | 시연 중 새로 가입하거나 `claude-e2e-user@movrit.local` |
| 운영자 | `claude-e2e-admin@movrit.local` |

> 비밀번호는 문서에 적지 않습니다. 시연 PC의 별도 보관 파일을 확인합니다.

## 1. 탐색 화면 (1분) — 비로그인

- `/home`: 배너, '신청 마감임박'·'선정확률 높은' 섹션, 카드의 "신청 N / 모집 M명"과 '마감 임박' 표시
- 상단 메뉴 **제품·지역·기자단·프리미어**: 서버의 캠페인 분류로 걸러집니다. 지역 메뉴에서 '서울' 선택, 미디어 칩·정렬 전환
- 카드의 찜 버튼 → 로그인 화면으로 안내되는 것 확인

## 2. 업체: 캠페인 등록 (2분) — `/seller/campaigns/new`

1. 운영 브랜드, 제목, 캠페인 종류(제품), 콘텐츠 채널(인스타그램), 모집 인원·기간 입력
2. **세부 일정**(선정 발표~결과 발표)과 **참여 안내**(미션·제출 요구사항·배송 안내) 입력
   - 선정 발표일을 모집 종료보다 앞으로 넣으면 저장 전에 순서 안내가 나옵니다.
3. 신청서: 참여 방식 '배송형' 체크, 대표 이미지 선택 → **캠페인 등록**
4. 사용자 화면 `/campaign/{id}`에서 일정표·미션·제출 요건이 그대로 보이는지 확인

## 3. 사용자: 가입 → 인증 → 신청 (2분)

1. `/signup`에서 가입 → 로그인 → 캠페인 상세의 이메일 인증
   - 시연 환경은 메일 대신 **인증번호가 화면에 표시**됩니다. '입력란에 채우기' → 확인
2. 신청서(신청 메시지·수령 정보·필수 동의) 작성 → **신청하기** → "신청이 접수되었습니다"
3. 카드 찜 → `/favorites`에 표시되는 것 확인

## 4. 업체: 선정 (1분) — `/seller/participants`

- 참여자 이름 → 포트폴리오(채널 지표·완료 이력) 확인 → **참여자 선정 → 확정**
- 이 시점에는 배송 연락처가 숨겨져 있습니다(참여 수락 전 개인정보 보호).

## 5. 사용자: 참여 수락 → 체험 확인 → 콘텐츠 제출 (2분) — `/mypage/campaigns`

1. **참여 수락 → 확인하여 반영** (이제 업체에 배송 연락처가 공개됩니다)
2. **체험 완료 확인 → 확인하여 반영**
3. 게시 채널·콘텐츠 URL 입력 → **콘텐츠 제출**

## 6. 업체 검토 → 운영자 최종 승인 (1분)

1. 업체 `/seller/contents`: **콘텐츠 검토 → 업체 검토 완료 → 저장**
2. 운영자 `/admin/content-reviews`: **콘텐츠 확인 → 처리 방법 '최종 승인' → 최종 승인**
   - 수정 요청을 고르면 의견을 꼭 입력해야 하고, 참여자가 고쳐 다시 제출할 수 있습니다.
3. 사용자 `/mypage/campaigns`: 상태 '완료', "운영자 최종 승인이 완료되었습니다" 확인, 알림 3건 도착

## 7. 운영자 관리 화면 (1분, 선택)

- `/admin/members`: 실제 회원 목록(검색·상태 필터) → 상세에서 정지·해제(본인 계정은 막힘)
- `/admin/reports`: 실제 DB 집계(신청·콘텐츠 상태별 건수, 완료율, 결제·환불 금액)와 최근 운영 기록
- `/admin/content`: 공지 작성·게시 → 사용자 `/notices`에 바로 표시
- 관리자 메뉴의 모든 화면(회원·업체·인플루언서·프리오더·주문·협업·정산·공지·리포트·설정)이 실제 데이터를 씁니다.

## 마무리 (보여줄 기술 포인트)

- 캠페인 신청 상태 흐름과 단계별 권한(업체·사용자·운영자)
- 버전 확인(동시 수정 충돌 409), 신청 내용 스냅샷, 연락처 공개 시점
- Flyway 마이그레이션과 자동 생성 ERD, 테스트(백엔드 117 · 프론트 131)와 화면 자동 점검 스크립트(`movrit-frontend/qa/e2e`)
- 상세 설계 이유: [architecture.md](architecture.md)

## 알려진 제약

- 카카오는 이메일을 주지 않아 계정 자동 병합이 되지 않습니다. 계정 설정에서 직접 연결합니다.
- 프리오더·주문·결제는 실제 결제사 연동 없이 상태 흐름만 구현되어 있습니다(신규 확장 보류). 관리자 화면에서도 조회만 합니다.
